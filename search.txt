Pour la recherche, deux approches différentes sont possibles: on peut soit
générer à l'avance les représentations de recherche que l'on va utiliser en
transformant le texte de plusieurs manières (avec re2c ou équivalent); ou bien
ne pas transformer le texte et construire une expression régulière qui sera
évaluée au moment de la recherche. La seconde approche est la plus souple et
peut aussi éventuellement mobiliser la première pour optimiser certains types de
recherches (en construisant un cache, basiquement). Donc partons là-dessus.

Pour simplifier les choses du point de vue du traitement des langues, il faut
avoir deux chaînes de traitement: une pour les langues modernes (qui sera
utilisée pour les champs summary, translation, etc.), et une autre pour les
langues anciennes (qui sera utilisée seulement pour le champ édition). Il peut y
avoir des passages en langues anciennes au milieu d'un passage en langue
moderne, pour l'instant n'essayons pas de régler ce cas.

Dans le cas des langues modernes, on devrait en principe vérifier que la fin de
chaque match est un grapheme cluster boundary, en ajoutant implicitement un
test. Mais pour l'instant, par économie, ne le faisons pas; à noter que la
librairie go regexp ne peut pas vérifier les grapheme boundaries, donc pour le
faire, il faudrait réimplémenter le regex engine. Il vaut mieux ne pas convertir
les multigraphes du type "ai", "au", "kh", mais en revanche on devrait convertir
"r̥" en "ṛ", etc., pour minimiser les problèmes liés aux multigraphes.

Dans le cas des langues anciennes, il faut d'abord convertir les multigraphes en
un seul code point. L'idée est de faire en sorte qu'en cherchant "a", on ne
trouve pas "ai" ou "au", et qu'en cherchant "r", on ne trouve pas "r̥".
Ultimement, il ne devrait plus y avoir de multigraphes dans le texte. De plus,
on peut aussi décider de convertir l'UTF-8 vers un encodage qui n'est pas
variable-length, si l'on évalue "manuellement" l'automate plutôt que d'employer
le module regexp. Dans les deux cas, il faut éventuellement simplifier des
séquences de grapheme clusters, en retirant des signes diacritiques par exemple,
quand on ne peut rien faire de mieux que cela.

Pour les transformations, que faire en python, et que faire en go? Les
transformations pour lesquelles on a besoin de connaître la langue seraient
peut-être plus commodes à faire en python, car on devrait autrement trouver un
moyen de passer la langue au code go, ce qui n'est pas pratique. En même temps,
il est plus rapide et plus facile de faire la transformation en go (avec re2c),
et il serait sans doute utile que le code go connaisse la langue des portions de
texte, pour permettre ensuite de filtrer les passages par langue. Si l'on permet
cela, il faut trouver une stratégie d'encodage pour encoder la langue, en
passant par exemple des séries d'intervalles (start, end, lang) pour chaque
segment du texte. Autre avantage de faire les transformations en go: on n'a pas
besoin de mettre à jour la base de données à chaque fois que l'on modifie les
transformations (mais en retour ça prend plus de temps de charger en mémoire la
base de données). Mais si on réalise les transformations en go, il faudrait
également écrire le code de manipulation de FSA en go. Donc restons à python
pour l'instant. En fait non, parce qu'il ne s'agit pas seulement de transformer
le texte, il faut que l'on maintienne une table d'offsets pour la surbrillance.
Donc il faut faire cela en python.

Il peut valoir la peine de ne pas utiliser le module regexp pour la recherche.
Si on manipule déjà à l'avance l'automate, autant carrément le rendre
déterministe, le minimiser et envoyer le tableau des transitions au code go, qui
appliquerait simplement une boucle d'évaluation. On devrait faire cela au moins
pour les textes sources, éventuellement pour d'autres champs. Mais il faudrait
s'assurer à l'avance que la boucle de matching fonctionne bien, donc il faudrait
commencer par écrire cela.

	# at the end of a word (viz. before a non-alphanumeric char or the empty

class Automaton:

	def __init__(self):
		self.states = []
		self.start_state = self.add_state()

	def add_state(self):
		ret = State()
		self.states.append(ret)
		return ret

	@classmethod
	def from_string(cls, s):
		aut = Automaton()
		state = aut.start_state
		for c in s:
			next_state = aut.add_state()
			state.add_transition(c, next_state)
			state = next_state
		state.final = True
		return aut

class State:

	def __init__(self):
		self.transitions = {}
		self.final = False

	def add_transition(self, symbol, target):
		assert not symbol in self.transitions
		self.transitions[symbol] = target

def apply_table(aut, table):
	for state in aut.states:
		transitions = list(state.transitions.items())
		for symbol, target_state in transitions:
			match = table.get(symbol)
			if match is None:
				continue
			state.add_transition(match, target_state)

def two_ways(table):
	for k, v in list(table.items()):
		assert not v in table
		table[v] = k
